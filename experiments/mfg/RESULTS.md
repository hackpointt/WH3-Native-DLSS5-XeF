# WH3 DLSS-G / MFG experiment status (2026-09-26)

**Not working; do not install this branch as a replacement for the validated DLSS5 + XeFG setup.**

The original OptiScaler DLSS-G path failed to create WH3's DX11-to-DX12 presenter swapchain with `0x887A0001`. Removing `DXGI_USAGE_UNORDERED_ACCESS` from the WH3-only DLSS-G descriptor allows Streamline to create the swapchain and report its interpolation capacity.

After that creation, DLSS5 Feed 1.17.0-beta.3 on its private D3D12 device consistently fails to close the command list used during native DLSS `CreateFeature` (`0x80070057`). Its first `Evaluate` then raises `0xC0000005`. OptiScaler reports native DLSS inactive, Depth/MV unavailable, and DLSS-G off. The same failure occurs with MFG Unlock removed and with both locally available Streamline versions (2.14.1 and the older RHI cached 2.14.0 package).

The identical OptiScaler DLL switched to XeFG instead of DLSS-G succeeds: DLSS5 Feed continues evaluating for thousands of frames, the WH3 bridge reports native NGX active and Depth/MV ready, and XeFG dispatches. This localizes the regression to initialization of the Streamline/DLSS-G presenter, rather than the WH3 native-DLSS input bridge or MFG Unlock alone.

An attempted delay unloaded `sl::kFeatureDLSS_G` **after** constructing its swapchain and requested reload after the first successful native DLSS evaluation. The unload returned `eOk`, but the Feed still failed during `CreateFeature` before that success point. This delayed-load patch is a failed diagnostic experiment, not a fix. NVIDIA's [Streamline programming guide](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS_G.md) specifies that switching between a native and DLSS-G proxy swapchain requires releasing and recreating the swapchain with the feature in the corresponding loaded state.

The game installation was restored to the pre-experiment DLL and INI hashes after each failed test. Local logs and snapshots are under `D:\DLSS5-Audit\2026-09-25-refresh`.

## Next candidate: two-stage swapchain

The current branch now contains an untested successor to the failed delayed-load patch. For WH3's legacy DXGI swapchain path, it starts with an ordinary DX12 presenter so the DLSS5 Feed can initialize. After the first successful native DLSS evaluation, it waits for both queues, releases the plain presenter and interop resources, and creates a new Streamline DLSS-G presenter. If creation fails, it attempts to restore the ordinary presenter. This is an experimental build candidate; successful compilation does not establish runtime compatibility or 4× output. The validated game installation remains untouched until a separate test is arranged.

The first two-stage test still failed before native DLSS evaluation. The ordinary presenter was created at 16:47:58, but OptiScaler's D3D12 device hook had loaded Streamline at 16:47:45. The Feed then reproduced the same command-list `Close()` error (`0x80070057`) and first-evaluation access violation. The next candidate gates all OptiScaler Streamline loading for WH3 until the first successful native DLSS evaluation. It is not yet runtime validated.

The deferred-Streamline candidate built from `423328e` passed its first 3D test. Native DLSS evaluated before Streamline loaded, then the plain DX12 presenter was recreated as a Streamline proxy. Feed delivered roughly 8,000 frames without the previous crash, the WH3 bridge reported native NGX active and depth/motion vectors ready, and Streamline reported a maximum of five generated frames. With `InterpolationCount=1`, Streamline logged transitions into `eOn, numFramesToGenerate=1` while the game window had focus. The menu screenshot showed `DLSSG state: OFF` after the overlay took focus; Streamline explicitly logged disabling interpolation when the game window lost focus. This establishes the startup-order fix and active 2× DLSS-G intervals, but does not yet measure sustained generated-output count or validate 4×. Logs and the 2× configuration are saved locally in `D:\DLSS5-Audit\2026-09-25-refresh\two-stage-2x-success-20260926`.

The follow-up 4× run changed only `[DLSSG] InterpolationCount` from `1` to `3`. Streamline logged `eOn, numFramesToGenerate=3` eleven times, including one continuous enabled interval of approximately 59 seconds. The native DLSS bridge reached tick 7,800 with depth and motion vectors ready; the Feed reported no evaluate crash or stopped state. Streamline also reported occasional interpolation pauses and one late `eDLSSGStatusFailReflexNotDetectedAtRuntime` near a second ReShade runtime creation. This confirms the 4× request reached the active Streamline path, but a user visual-quality report and a direct output-frame measurement are still pending. The run logs and exact configuration are saved in `D:\DLSS5-Audit\2026-09-25-refresh\two-stage-4x-run-20260926`.

**Correction after reviewing the DLSS5 Feed log:** This branch is based on upstream OptiScaler and does not contain the DLSS-NR feature-18 hook. The 4× run explicitly reported `neural forwarder NOT loaded, neural model (feature 18) NOT loaded; OptiScaler is upscaling and nothing more.` Native DLSS NGX being active does not establish DLSS5 Neural Rendering. The visible 4× result therefore does **not** satisfy the requested DLSS5 + MFG combination. The follow-up fork-aware build is on `experiment/wh3-dlssnr-mfg-20260926`; it must pass a same-run Feed neural-model check and Streamline MFG check before being called successful.
